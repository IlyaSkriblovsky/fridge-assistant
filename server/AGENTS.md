# Assistant Server

Бэкенд персонального голосового ассистента. Прибор Seeed reTerminal Sticky
(E1005) на холодильнике присылает голосовой запрос на `POST /audio`, сервер его
выполняет, в том числе во внешних сервисах, и отвечает текстом, который прибор
показывает на ePaper. Один пользователь, один прибор и один статичный токен
прибора: так задумано.

Запись уходит в Gemini API (`generateContent`, модель
`gemini-3.5-flash-lite`, бесплатный уровень, см. `docs/vision.md`) вместе с
описаниями функций ассистента. Модель вызывает функции, сервер их выполняет, а
последний текст модели уходит на прибор. Пока функция одна: добавить пункты в
список покупок в Google Keep через неофициальную `gkeepapi` (см.
`docs/use-cases/shopping-list.md`). Сервер пока пишет в тестовую заметку, а не
в семейный список.

| `shopping_list.py` | Список покупок в Keep через gkeepapi |

| `Dockerfile` | Образ для деплоя. CI (`../.github/workflows/server.yml`) собирает его и с `main` пушит в GHCR, см. `docs/server.md` |

| `experiments/` | Пробные скрипты, не часть сервера. Зависимости объявлены в самом скрипте (PEP 723), запуск: `uv run --env-file .env experiments/<script>.py` |
| `docs/vision.md` | Замысел, прибор, принятые решения, список сценариев |
| `docs/device-contract.md` | Контракт с прошивкой: запрос, потоковое тело, ответ, ошибки |

Прошивка прибора лежит в `../firmware/`. Общий контракт —
`docs/device-contract.md`; поведение и настройки прошивки — её
`docs/project-vision.md` и `src/config.h`.

## Команды

```sh
uv sync                                # зависимости
uv run pytest                          # автономные тесты, без .env и сети
uv run --env-file .env python main.py  # сервер на 0.0.0.0:8000, печатает URL для прибора
curl -X POST --data-binary @recordings/<file>.wav -H "Content-Type: audio/wav" \
  -H "Authorization: Bearer $DEVICE_TOKEN" \
  http://localhost:8000/audio          # по-настоящему меняет список в Keep
docker build -t fridge-assistant-server .  # образ, как его собирает CI
```

## Что важно не сломать

- **Контракт `/audio` общий с прошивкой.** Если он меняется, меняются оба
  проекта. Прибор читает из ответа только строковое поле `response`, и
  отсутствие этого поля он показывает как ошибку.
- **Недоработки прошивки — не ограничения сервера.** Длина текста на экране,
  таймаут ожидания ответа: прошивку подгоняют под сервер, а не наоборот. Не
  обрезай ответы ради текущей прошивки и не приводи текст к тому, что она
  умеет рисовать. Исключений здесь больше нет: `translit.py` был последним, и
  его удалили, когда прибор научился кириллице, греческому и типографике.
  Ответ уходит на прибор ровно таким, каким его дала модель.
- **Тело приходит потоком, пока кнопка зажата, и длины в WAV-заголовке равны
  `0xFFFFFFFF`.** Тело копится в памяти не больше `MAX_AUDIO_BYTES`, на диск
  записи не пишутся, и длинам из заголовка верить нельзя. Поток можно
  передавать во внешний сервис, не дожидаясь его конца, но пока этого не
  делаем: `generateContent` получает запись целиком, когда тело закончилось.
  Потоковая передача понадобится, если перейдём на Live API.
- **Оборванный запрос не выполняется.** Прибор уже показал ошибку, и вопрос
  зададут снова. Выполнишь его — пункт окажется в списке дважды.
- **Сервер дочитывает тело до конца, прежде чем ответить**, в том числе в
  `/audio/fault/*`, при отказе по токену и когда запись длиннее лимита. Иначе
  прибор покажет `NO SERVER` вместо ответа или проверяемого сбоя.
- **Каждый эндпоинт требует токен прибора.** Это `authorize()`, общая
  зависимость приложения. Новый эндпоинт получает её сам, не выключай её для
  него. Сервер знает один статичный токен, `DEVICE_TOKEN`, и так задумано.
  Пользователей, учётных записей и выдачи токенов нет, без запроса их не
  добавляй.
- **В Keep сервер ходит только под аккаунтом ассистента.** С ним расшарен один
  список покупок, а master token открывает весь аккаунт, поэтому основные
  аккаунты семьи не подключай. Состояние Keep не храни на диске:
  синхронизируй с нуля на каждый запрос, для одного списка это меньше секунды.
- **Образ берёт из `server/` только `pyproject.toml`, `uv.lock` и `*.py` из
  корня.** Подкаталог с модулями или файл, который сервер читает, нужно
  добавить в `Dockerfile`, иначе локально всё работает, а на сервере нет.
  Смоук-тест в CI поймает только то, без чего сервер не стартует.
- **Открытые вопросы не решаются молча.** Хостинг, уровень Gemini API, а
  также смена AI, модели, сервиса для списка покупок или переход на Live API —
  это решения пользователя. Предлагай варианты, а принятое решение
  записывай в `docs/vision.md` или в документ сценария и удаляй вопрос из
  `docs/open-questions.md`.

## Тестирование

Тесты находятся в `tests/`, настройки pytest — в `pyproject.toml`, зависимости —
в группе `dev`. Из корня репозитория запуск: `cd server && uv run pytest`.
После изменения бэкенда запускай этот набор. CI запускает его на Python 3.12
перед сборкой и публикацией образа; Docker smoke test сохраняется отдельно.

Не используй реальные секреты, сеть или записи из `recordings/` в тестах.
Общие фикстуры блокируют внешние клиенты и сетевые подключения, задают
фиктивные настройки. Подменяй границы Gemini и Keep, используй настоящие
объекты заметок в памяти. Потоковые гарантии проверяй ASGI-событиями:
буферизованный HTTP-клиент сам по себе не доказывает дочитывание тела.

## Документация

Документы в `docs/` написаны на русском, код и комментарии в нём — на
английском. Когда меняется поведение сервера, обнови `docs/server.md`. Новый
сценарий получает свой файл в `docs/use-cases/` и строку в таблице в
`docs/vision.md`.
