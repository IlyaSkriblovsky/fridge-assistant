# Сервер: как устроен сейчас

Принимает голосовой вопрос с прибора, отдаёт его Gemini вместе с функциями,
которые может вызывать ассистент, выполняет эти вызовы и возвращает на прибор
ответ модели. Пока функция одна: добавить в список покупок в Google Keep.

FastAPI-приложение, запускается через uvicorn. Зависимости в `pyproject.toml`,
ставятся через `uv`.

## Запуск

```sh
uv sync
uv run --env-file .env python main.py
```

Без `--env-file .env` сервер не стартует: ключи и настройки лежат в `.env`.

При старте сервер печатает модель, заметку Keep и адрес, который нужно
вписать в прибор (`kBackendBaseUrl` в `src/config.h` прошивки):

```
  Assistant server
  model      -> gemini-3.5-flash-lite
  Keep list  -> 1789753509102.1788216170
  listening  -> 0.0.0.0:8000

  Put this URL into the device (same WiFi network):
    http://192.168.1.42:8000/audio
  Public IP (needs port forwarding to be reachable): 203.0.113.7
```

Прибор в той же WiFi-сети ходит по локальному адресу. Публичный IP печатается
на случай, если понадобится доступ снаружи. Сам по себе он не заработает, нужен
проброс порта на роутере.

Переменные окружения:

| Переменная | По умолчанию | Что |
| --- | --- | --- |
| `GEMINI_API_KEY` | обязательна | Ключ Gemini API из AI Studio |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` | Модель |
| `KEEP_EMAIL` | обязательна | Google-аккаунт ассистента |
| `KEEP_MASTER_TOKEN` | обязательна | Его master token, как получить — в docstring `experiments/keep_list.py` |
| `KEEP_NOTE_ID` | обязательна | Id заметки со списком покупок, его показывает `experiments/keep_list.py lists` |
| `HOST` | `0.0.0.0` | Адрес, который слушает сервер |
| `PORT` | `8000` | Порт |

Если обязательной переменной нет, сервер не запускается и называет её.

## `POST /audio`

Тело запроса — WAV. Content-Type не проверяется. Прибор шлёт тело потоком
(`Transfer-Encoding: chunked`), пока кнопка ещё зажата, см.
[device-contract.md](device-contract.md).

### Запись

Тело копится в памяти, на диск ничего не пишется. Больше `MAX_AUDIO_BYTES`
(10 МБ, это минуты звука) сервер не хранит. Прибор пишет не дольше 30 с, это
меньше 1 МБ, а Gemini принимает запрос до 20 МБ.

В момент отправки заголовка длина записи ещё неизвестна, поэтому оба поля
длины в WAV-заголовке приходят как `0xFFFFFFFF`. Когда тело пришло целиком,
`settle_wav_lengths()` вписывает настоящие длины. Трогает она только поля,
равные `0xFFFFFFFF`, а чанк `data` ищет обходом чанков, а не по смещению 36.

### Ответ

Запись целиком уходит в `generateContent` (`assistant.answer()`), вместе с
системной инструкцией и описаниями функций. Модель распознаёт речь и вызывает
функции. Сервер выполняет вызовы и отправляет модели результаты, пока она не
ответит текстом. Больше пяти раундов (`MAX_ROUNDS`) сервер не ждёт. Запись
после этого выбрасывается.

Текст модели уходит на прибор, пропущенный через временный транслитератор
([deferred.md](deferred.md#транслитерация-ответов)):

```json
{ "response": "Dobavila moloko i pechen'e v spisok pokupok." }
```

### Функции ассистента

| Функция | Что делает |
| --- | --- |
| `add_to_shopping_list(items)` | Добавляет пункты в список покупок Keep, см. [shopping-list.md](use-cases/shopping-list.md) |

Функции синхронные и выполняются в отдельном потоке (`asyncio.to_thread`).
Если функция не справилась, она возвращает модели ошибку, и модель говорит о
ней в ответе.

### Если что-то пошло не так

Прибор показывает как ответ любой `200` со строкой в `response`. Поэтому о
своих сбоях сервер пока говорит обычным ответом
([deferred.md](deferred.md#ошибки-как-обычный-ответ)):

| Что случилось | Что сервер делает | Что в `response` (до транслитерации) |
| --- | --- | --- |
| Поток оборвался | Ничего не выполняет: прибор уже показал ошибку, и вопрос зададут снова | Пустая строка, её некому читать |
| Запись больше `MAX_AUDIO_BYTES` | Дочитывает тело, в Gemini не отправляет | «Слишком длинная запись.» |
| Gemini вернул ошибку | — | «Gemini ответил ошибкой 400, попробуй ещё раз.» |
| До Gemini не достучаться | — | «Не получилось связаться с Gemini, попробуй ещё раз.» |
| Модель не ответила текстом | — | «Не получилось ответить, попробуй ещё раз.» |
| Keep не сработал | Отдаёт модели ошибку | Что скажет модель |

Лишнее тело сервер дочитывает до конца, прежде чем ответить: иначе соединение
закроется под прибором, и он покажет `NO SERVER`.

### Лог

Записи не сохраняются, поэтому всё, что нужно для разбора, пишется в консоль:
WAV-заголовок, раунды Gemini с токенами, вызовы функций с результатом и
ответ. Время ответа отсчитывается от конца тела: столько ждёт прибор, и это
время ограничено его `kResponseTimeoutMs`.

```
[20260919-030618-572] 156716 bytes chunked over 4.93 s  content-type=audio/wav  16000 Hz, 1 ch, 16-bit, 4.90 s  (lengths filled in)
[20260919-030618-572] gemini round 1: 1.54 s, tokens in 390, out 28, thinking 0
[20260919-030618-572] -> add_to_shopping_list({'items': ['молоко', 'печенье']}) => {'items': [{'item': 'молоко', 'result': 'restored'}, {'item': 'печенье', 'result': 'added'}]}  1.31 s
[20260919-030618-572] gemini round 2: 2.06 s, tokens in 462, out 13, thinking 0
[20260919-030618-572] reply: Добавила молоко и печенье в список покупок.  (4.92 s after the body ended)
```

### Проверка

```sh
curl -X POST --data-binary @question.wav -H "Content-Type: audio/wav" \
  http://localhost:8000/audio
```

Записи, сделанные прототипом, лежат в `recordings/`. Каждый такой запрос
по-настоящему меняет список в Keep.

## Намеренные сбои

Прошивка различает четыре плохих исхода запроса: `NO SERVER`, `SERVER ERROR`,
`BAD RESPONSE`, `TIMED OUT`. Три из них от работающего сервера получить
невозможно, поэтому для них есть отдельные эндпоинты. Они ничего не
сохраняют и в Gemini не ходят:

| Эндпоинт | Что делает | Что показывает прибор |
| --- | --- | --- |
| `POST /audio/fault/500` | Отвечает `500` | `SERVER ERROR 500` |
| `POST /audio/fault/empty` | Отвечает `200` и `{}` | `BAD RESPONSE` |
| `POST /audio/fault/slow` | Молчит `FAULT_DELAY_SECONDS` (45 с) | `TIMED OUT` |

Для `NO SERVER` сервер вовсе не нужен: прошивка сама стучится на закрытый порт
и на адрес, где никого нет.

Все три эндпоинта дочитывают тело запроса до конца, прежде чем ответить (это
делает `drain()`). Иначе соединение закроется под прибором, который ещё не
закончил загрузку, и он покажет `NO SERVER` вместо проверяемого случая.

`FAULT_DELAY_SECONDS` должна быть больше `kResponseTimeoutMs` прошивки (сейчас
30 с), чтобы прибор сдался первым. Если в прошивке таймаут увеличат, это
значение нужно поднять вслед за ним.

## Устройство

| Где | Что |
| --- | --- |
| `main.py` | FastAPI-приложение: `POST /audio`, намеренные сбои, запуск |
| `main.py`: `settle_wav_lengths()`, `describe_wav()` | Длины в заголовке потокового WAV, строка с его параметрами для лога |
| `assistant.py` | Gemini: системная инструкция, описания функций, цикл вызовов |
| `shopping_list.py` | Список покупок в Keep через gkeepapi |
| `translit.py` | Временная транслитерация ответа для прибора |
