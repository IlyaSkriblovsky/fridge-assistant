# Сервер: как устроен сейчас

Принимает голосовой вопрос с прибора, отдаёт его Gemini вместе с функциями,
которые может вызывать ассистент, выполняет эти вызовы и возвращает на прибор
ответ модели. Пока функция одна: добавить в список покупок в Google Keep.

FastAPI-приложение, запускается через uvicorn. Зависимости в `pyproject.toml`,
ставятся через `uv`.

## Запуск

```sh
uv sync
uv run --env-file .env python main.py
```

Без `--env-file .env` сервер не стартует: ключи и настройки лежат в `.env`.

При старте сервер печатает модель, заметку Keep и адрес, который нужно
вписать в прибор (`kBackendBaseUrl` в `src/secrets.h` прошивки):

```
  Assistant server
  model      -> gemini-3.5-flash-lite
  Keep list  -> 1789753509102.1788216170
  listening  -> 0.0.0.0:8000

  Put this URL into the device (same WiFi network):
    http://192.168.1.42:8000/audio
  Public IP (needs port forwarding to be reachable): 203.0.113.7
```

Прибор в той же WiFi-сети ходит по локальному адресу. Публичный IP печатается
на случай, если понадобится доступ снаружи. Сам по себе он не заработает, нужен
проброс порта на роутере.

Переменные окружения:

| Переменная | По умолчанию | Что |
| --- | --- | --- |
| `GEMINI_API_KEY` | обязательна | Ключ Gemini API из AI Studio |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` | Модель |
| `KEEP_EMAIL` | обязательна | Google-аккаунт ассистента |
| `KEEP_MASTER_TOKEN` | обязательна | Его master token, как получить — в docstring `experiments/keep_list.py` |
| `KEEP_NOTE_ID` | обязательна | Id заметки со списком покупок, его показывает `experiments/keep_list.py lists` |
| `DEVICE_TOKEN` | обязательна | Токен прибора, тот же, что `kDeviceToken` в `src/secrets.h` прошивки, см. [Токен прибора](#токен-прибора) |
| `HOST` | `0.0.0.0` | Адрес, который слушает сервер |
| `PORT` | `8000` | Порт |
| `WEATHER_LATITUDE`, `WEATHER_LONGITUDE` | не заданы | Координаты прогноза Open-Meteo; задаются парой |
| `DATABASE_PATH` | `data/dashboard.sqlite3` (Docker: `/data/dashboard.sqlite3`) | Файл SQLite с показателями дашборда |

Если обязательной переменной нет, сервер не запускается и называет её.

## Токен прибора

Каждый запрос, к `/audio`, дашборду и [намеренным сбоям](#намеренные-сбои), должен нести
заголовок `Authorization: Bearer <DEVICE_TOKEN>`. Это делает зависимость
`authorize()`, общая для всех эндпоинтов. Токен статичный, один на прибор и
сервер, почему так — в [vision.md](vision.md#один-пользователь-один-прибор-один-токен).
Сгенерировать новый:

```sh
python3 -c 'import secrets; print(secrets.token_urlsafe(32))'
```

Запрос без токена или с чужим токеном сервер не выполняет и отвечает `401`.
Прибор показывает это как `SERVER ERROR 401`. Тело перед этим дочитывается до
конца, как и в остальных случаях: иначе прибор показал бы `NO SERVER`. В лог
пишется одна строка, из которой видно, пришёл ли токен вообще:

```
[auth] POST /audio from 203.0.113.7: wrong token
```

## `POST /audio`

Тело запроса — WAV. Content-Type не проверяется. Прибор шлёт тело потоком
(`Transfer-Encoding: chunked`), пока кнопка ещё зажата, см.
[device-contract.md](device-contract.md).

### Запись

Тело копится в памяти, на диск ничего не пишется. Больше `MAX_AUDIO_BYTES`
(10 МБ, это минуты звука) сервер не хранит. Прибор пишет не дольше 30 с, это
меньше 1 МБ, а Gemini принимает запрос до 20 МБ.

В момент отправки заголовка длина записи ещё неизвестна, поэтому оба поля
длины в WAV-заголовке приходят как `0xFFFFFFFF`. Когда тело пришло целиком,
`settle_wav_lengths()` вписывает настоящие длины. Трогает она только поля,
равные `0xFFFFFFFF`, а чанк `data` ищет обходом чанков, а не по смещению 36.

### Ответ

Запись целиком уходит в `generateContent` (`assistant.answer()`), вместе с
системной инструкцией и описаниями функций. Модель распознаёт речь и вызывает
функции. Сервер выполняет вызовы и отправляет модели результаты, пока она не
ответит текстом. Больше пяти раундов (`MAX_ROUNDS`) сервер не ждёт. Запись
после этого выбрасывается.

Текст модели уходит на прибор, пропущенный через временный транслитератор
([deferred.md](deferred.md#транслитерация-ответов)):

```json
{ "response": "Dobavila moloko i pechen'e v spisok pokupok." }
```

### Функции ассистента

| Функция | Что делает |
| --- | --- |
| `add_to_shopping_list(items)` | Добавляет пункты в список покупок Keep, см. [shopping-list.md](use-cases/shopping-list.md) |

Функции синхронные и выполняются в отдельном потоке (`asyncio.to_thread`).
Если функция не справилась, она возвращает модели ошибку, и модель говорит о
ней в ответе.

### Если что-то пошло не так

Прибор показывает как ответ любой `200` со строкой в `response`. Поэтому о
своих сбоях сервер пока говорит обычным ответом
([deferred.md](deferred.md#ошибки-как-обычный-ответ)):

| Что случилось | Что сервер делает | Что в `response` (до транслитерации) |
| --- | --- | --- |
| Поток оборвался | Ничего не выполняет: прибор уже показал ошибку, и вопрос зададут снова | Пустая строка, её некому читать |
| Запись больше `MAX_AUDIO_BYTES` | Дочитывает тело, в Gemini не отправляет | «Слишком длинная запись.» |
| Gemini вернул ошибку | — | «Gemini ответил ошибкой 400, попробуй ещё раз.» |
| До Gemini не достучаться | — | «Не получилось связаться с Gemini, попробуй ещё раз.» |
| Модель не ответила текстом | — | «Не получилось ответить, попробуй ещё раз.» |
| Keep не сработал | Отдаёт модели ошибку | Что скажет модель |

Лишнее тело сервер дочитывает до конца, прежде чем ответить: иначе соединение
закроется под прибором, и он покажет `NO SERVER`.

### Лог

Записи не сохраняются, поэтому всё, что нужно для разбора, пишется в консоль:
WAV-заголовок, раунды Gemini с токенами, вызовы функций с результатом и
ответ. Время ответа отсчитывается от конца тела: столько ждёт прибор, и это
время ограничено его `kResponseTimeoutMs`.

```
[20260919-030618-572] 156716 bytes chunked over 4.93 s  content-type=audio/wav  16000 Hz, 1 ch, 16-bit, 4.90 s  (lengths filled in)
[20260919-030618-572] gemini round 1: 1.54 s, tokens in 390, out 28, thinking 0
[20260919-030618-572] -> add_to_shopping_list({'items': ['молоко', 'печенье']}) => {'items': [{'item': 'молоко', 'result': 'restored'}, {'item': 'печенье', 'result': 'added'}]}  1.31 s
[20260919-030618-572] gemini round 2: 2.06 s, tokens in 462, out 13, thinking 0
[20260919-030618-572] reply: Добавила молоко и печенье в список покупок.  (4.92 s after the body ended)
```

### Проверка

```sh
curl -X POST --data-binary @question.wav -H "Content-Type: audio/wav" \
  -H "Authorization: Bearer $DEVICE_TOKEN" http://localhost:8000/audio
```

Записи, сделанные прототипом, лежат в `recordings/`. Каждый такой запрос
по-настоящему меняет список в Keep.

## `GET /sticky/dashboard`

Сервер рисует готовый монохромный кадр 800×480 в `dashboard.py` через Pillow.
На экране — число непустых неотмеченных пунктов списка покупок из SQLite.
Подпись согласуется с числом: «1 пункт», «2 пункта», «5 пунктов», включая
исключение для 11–14. Порог устаревания задаёт
`dashboard.SHOPPING_STALE_AFTER_SECONDS` (45 минут).
Пустые строки и уже купленное не считаются; одинаковые отдельные строки
считаются отдельно. Запрос дашборда не обращается к Keep. До первого успешного
обновления вместо числа показано «—», после 45 минут без свежих данных —
«Данные давно не обновлялись». Последнее успешное число сохраняется при сбоях.
В верхней строке сервер рисует прежние индикаторы прибора: батарейку с
процентом слева и температуру/влажность (`23.4°  48.2%`) справа. При отсутствии
данных — `?`, `--°` и `--%`. Шрифт GNU FreeSans Bold хранится в `fonts/` и
копируется в Docker-образ. На голосовых экранах прошивка их больше не рисует;
датчики читаются перед запросом дашборда.
Рендер выполняется в thread pool FastAPI, не блокируя async `/audio`.

- Всегда возвращает однобитный `image/png`, `Dashboard-Format: png`.
  Размер 800×480, grayscale 1 bit, без interlace и прозрачности.
  Параметра выбора формата нет.
- Необязательные параметры: `battery_pct` (целое 0–100), `temperature_c`
  (конечное число), `humidity_pct` (0–100). Пропущенные показания рисуются
  как неизвестные; некорректные значения дают `422`.
- Ответ содержит `Next-Update-After: 3600` и `Cache-Control: no-store`.

```sh
curl -fsS -H "Authorization: Bearer $DEVICE_TOKEN" \
  'http://localhost:8000/sticky/dashboard?battery_pct=76&temperature_c=23.4&humidity_pct=48.2' \
  -o dashboard.png
```

Для просмотра непосредственно в браузере откройте
`http://localhost:8000/sticky/dashboard` (или URL своего сервера).
В стандартном диалоге входа логин — `sticky`, пароль — `DEVICE_TOKEN`.
Это дополнительный способ передать тот же секрет только для дашборда;
авторизация остаётся в общей зависимости приложения. Токен в query string
не поддерживается. Прибор использует Bearer и декодирует PNG перед отрисовкой.

Подробности упаковки, зарезервированные области локальных индикаторов и
срок следующего запроса — в [контракте](device-contract.md#дашборд).
Описание содержимого и дальнейшая приёмка — в
[idle-screen.md](use-cases/idle-screen.md).

## Хранение и фоновые задачи

`metrics.py` хранит в SQLite ключ показателя, целое значение и время успешного
обновления (Unix timestamp). Счётчик привязан к `KEEP_NOTE_ID`: смена заметки
не покажет число из старого списка. Полное состояние Keep и тексты покупок
в базе не сохраняются. Каталог и таблица создаются при старте; ошибка открытия
базы останавливает запуск.

`jobs.periodic()` запускается из lifespan FastAPI: первая попытка сразу в фоне,
следующие — через 900 секунд после завершения предыдущей. Между 21:00
(включительно) и 06:00 по `Asia/Nicosia` опрос приостановлен, в том числе
при ночном запуске сервера; возобновляется в 06:00. Переходы летнего времени
учитываются. Голосовые изменения обновляют счётчик и ночью. Синхронный код
выполняется через `asyncio.to_thread`. Ошибки пишутся в лог и не останавливают
следующие попытки. Для будущего источника можно запустить отдельную такую
задачу со своим интервалом и ключом в базе.

Инструмент добавления делает первую букву пункта заглавной, сохраняя
регистр остального текста (например, `молоко UHT` → `Молоко UHT`). Это
касается и повторно запрошенных, и восстановленных отмеченных пунктов.

После успешной записи голосовым инструментом число пересчитывается по
синхронизированной заметке и сохраняется до возврата результата модели.
Общий lock сериализует операции Keep вместе с публикацией результата:
фоновый снимок не может затереть более свежую голосовую правку. Если Keep
занят больше 10 секунд, голосовой инструмент возвращает ошибку занятости.
Ошибка SQLite после успешной правки логируется, но не превращается в ошибку
добавления: изменение уже произошло, следующая фоновая попытка восстановит счётчик.

Запускать **один процесс / один worker / одну реплику**. Расписание находится
в памяти; пропущенные при выключении запуски не воспроизводятся — при старте
читаем актуальное состояние сразу днём или в 06:00 после ночного запуска. Постоянная очередь и отдельный планировщик
понадобятся при нескольких процессах или задачах, которые нельзя пропускать.
Отмена asyncio-задачи при остановке не прерывает уже выполняющийся поток
`gkeepapi`; у библиотеки нет публичной настройки общего таймаута операции.
Зависший запрос может потребовать перезапуска процесса; новые экземпляры
этой же фоновой операции поверх незавершённой не запускаются.

Интервал опроса Keep и интервал пробуждения прибора независимы: прибор пока
запрашивает экран раз в час и после голосового сценария.

## Погода на дашборде

Справа показан прогноз на сегодня и завтра: минимальная и максимальная
температура, описание со значком и максимальная за день вероятность осадков.
Источник — [Open-Meteo](https://open-meteo.com/en/docs); ключ API для этого
некоммерческого использования не нужен. Источник указан в документации;
на экране подписи источника нет, между блоками дней увеличен отступ.
Температура в верхней строке по-прежнему выводится без дополнительной подписи.

Задайте `WEATHER_LATITUDE` и `WEATHER_LONGITUDE` в окружении сервера.
Без координат показано «Нет прогноза», сетевые запросы не выполняются.
Если задана только одна координата или значение вне допустимого диапазона,
сервер остановится при запуске с ошибкой настройки.

`weather.py` получает три дня прогноза при старте и затем раз в час,
включая ночь. Это отдельная задача от списка покупок. HTTP-таймаут — 15 секунд.
Результат целиком сохраняется в таблице `forecasts` в той же SQLite;
таблица автоматически добавляется и в существующую базу. Снимки привязаны
к координатам и часовому поясу `Asia/Nicosia`.

Рендер читает только базу и выбирает сегодня/завтра по календарным датам
в `Asia/Nicosia`. Третий день позволяет корректно сменить даты в полночь
до очередного опроса. Если нужной даты нет, показано «Нет прогноза».
При ошибке HTTP или некорректном ответе сохраняется предыдущий снимок;
через три часа он помечается «Прогноз устарел» (`weather.STALE_AFTER_SECONDS`).
Неизвестная вероятность осадков показана прочерком, а не нулём.

## Намеренные сбои

Прошивка различает четыре плохих исхода запроса: `NO SERVER`, `SERVER ERROR`,
`BAD RESPONSE`, `TIMED OUT`. Три из них от работающего сервера получить
невозможно, поэтому для них есть отдельные эндпоинты. Они ничего не
сохраняют и в Gemini не ходят, но токен прибора им нужен так же, как `/audio`:

| Эндпоинт | Что делает | Что показывает прибор |
| --- | --- | --- |
| `POST /audio/fault/500` | Отвечает `500` | `SERVER ERROR 500` |
| `POST /audio/fault/empty` | Отвечает `200` и `{}` | `BAD RESPONSE` |
| `POST /audio/fault/slow` | Молчит `FAULT_DELAY_SECONDS` (45 с) | `TIMED OUT` |

Для `NO SERVER` сервер вовсе не нужен: прошивка сама стучится на закрытый порт
и на адрес, где никого нет.

Все три эндпоинта дочитывают тело запроса до конца, прежде чем ответить (это
делает `drain()`). Иначе соединение закроется под прибором, который ещё не
закончил загрузку, и он покажет `NO SERVER` вместо проверяемого случая.

`FAULT_DELAY_SECONDS` должна быть больше `kResponseTimeoutMs` прошивки (сейчас
30 с), чтобы прибор сдался первым. Если в прошивке таймаут увеличат, это
значение нужно поднять вслед за ним.

## Деплой

Сервер работает в Docker на арендованном сервере, за `nginxproxy/nginx-proxy`
и `nginxproxy/acme-companion`, которые там уже обслуживают другие проекты.
Образ собирает CI, а на сервере его запускает docker compose.

### Образ

`Dockerfile` ставит зависимости из `uv.lock` в virtualenv, кладёт рядом
модули `*.py` из корня `server/` и запускает `python main.py`, как при
локальном запуске. Секретов в образе нет, настройки приходят теми же
переменными окружения. Лог выводится через `print()`, поэтому в образе
выставлен `PYTHONUNBUFFERED=1`, иначе `docker logs` показывал бы его с
задержкой.

`.github/workflows/server.yml` запускается на каждый push и PR, который
трогает `server/`. Сначала отдельный job на Python 3.12 устанавливает зависимости через
`uv sync --locked` и запускает `uv run --locked pytest`. Тесты работают без
секретов и внешних сервисов. Падение тестов блокирует сборку и публикацию.
Локальный запуск из `server/`: `uv run pytest`; `.env` не нужен.

После успешных тестов CI собирает образ, запускает его с фиктивными настройками и
проверяет, что `POST /audio/fault/empty` с токеном отвечает `{}`, а без
токена — `401`. Также проверяются бинарный кадр и однобитный PNG дашборда.
Эти запросы не ходят ни в Gemini, ни в Keep. Образ из `main` после этого уходит в GHCR:

| Образ | Что |
| --- | --- |
| `ghcr.io/ilyaskriblovsky/fridge-assistant-server:latest` | Последний коммит в `main` |
| `ghcr.io/ilyaskriblovsky/fridge-assistant-server:sha-<коммит>` | Конкретный коммит, на него можно откатиться |

Образ собирается под `linux/amd64`. Собрать и запустить его локально:

```sh
docker build -t fridge-assistant-server .
docker run --rm -p 8000:8000 --env-file .env -v assistant-data:/data fridge-assistant-server
```

При старте в контейнере сервер печатает адрес самого контейнера. Прибору этот
адрес не подходит: за nginx-proxy прибор ходит на `http://<домен>/audio`.

База в `/data` требует постоянного тома, иначе замена контейнера потеряет
снимки. Именованный том получает права каталога из образа; при bind mount
нужно дать пользователю `assistant` право записи в каталог.

### За nginx-proxy

```yaml
services:
  assistant:
    image: ghcr.io/ilyaskriblovsky/fridge-assistant-server:latest
    restart: unless-stopped
    env_file: .env
    environment:
      VIRTUAL_HOST: assistant.example.com
      VIRTUAL_PORT: "8000"
      LETSENCRYPT_HOST: assistant.example.com
      HTTPS_METHOD: noredirect
      FORWARDED_ALLOW_IPS: "*"
    networks: [proxy]
    volumes:
      - assistant-data:/data

volumes:
  assistant-data:

networks:
  proxy:
    external: true
    name: <сеть, в которой nginx-proxy>
```

В `.env` на сервере те же переменные, что и локально, `DEVICE_TOKEN` в том
числе. Порты наружу не публикуются, до контейнера добирается только
nginx-proxy.

- **`HTTPS_METHOD: noredirect`.** По умолчанию nginx-proxy отвечает на HTTP
  редиректом `301` на HTTPS. Прошивка пока ходит только по HTTP (D5 в её
  `docs/deferred.md`) и редиректам не следует, поэтому прибор показал бы
  `SERVER ERROR 301`. Токен при этом идёт открытым текстом, см.
  [open-questions.md](open-questions.md). С `noredirect` домен отвечает и по HTTP, и по HTTPS, а
  HSTS nginx-proxy не включает.
- **`FORWARDED_ALLOW_IPS: "*"`.** uvicorn верит `X-Forwarded-For` только с
  `127.0.0.1`, поэтому без этой настройки в логе вместо адреса клиента был бы
  адрес nginx-proxy. Верить всем тут можно: до контейнера доходит только
  прокси.

Ещё два файла кладутся в каталог, который смонтирован в nginx-proxy как
`/etc/nginx/vhost.d`. Имя каждого файла начинается со значения `VIRTUAL_HOST`:

```nginx
# vhost.d/assistant.example.com
client_max_body_size 10m;
```

nginx по умолчанию не принимает тело больше 1 МБ, а 30 с записи — это 960 КБ.
Запись помещается, но впритык: если прибор начнёт писать дольше 32 с, nginx
ответит `413`, и до сервера запрос не дойдёт. 10 МБ — это `MAX_AUDIO_BYTES`.

```nginx
# vhost.d/assistant.example.com_location
proxy_request_buffering off;
```

Без этой настройки nginx сначала получает тело целиком и только потом отдаёт
его серверу, одним куском. Ответу это не мешает, но
[поток](device-contract.md#звук-приходит-потоком) до сервера не доходит: в
логе время загрузки получается нулевым, а пометки `chunked` нет.

Все четыре настройки проверены на `nginx-proxy` 1.11 с самоподписанным
сертификатом. Выпуск сертификата через acme-companion не проверялся.
